01 / RESEARCH

UX Research Summary

Binance · Bitget · BitMart의 검증된 UX 패턴을 기능 관점에서만 참고했습니다. 로고 · 색상 · 아이콘 · 트레이드 드레스는 사용하지 않았고, 각 패턴을 QuantumTrade AI 관점으로 재해석했습니다.

Binance
Referenced
  • 정보 밀도 — Symbol Header 12개 통계 필드의 압축 배치
  • 모듈 리사이즈 — 각 패널의 자유로운 크기 조절과 도크
  • Multi-Chart — 여러 심볼 동시 비교 UX
  • Advanced Modes — Fullscreen · Trader · Advanced 모드 전환
  • 주문장 정밀도 — Precision 선택 및 Amount/Cumulative 토글
Reframed → 24열 그리드 기반 자율 레이아웃 엔진으로 재구현. 위젯을 완전히 분리된 컴포넌트로 만들어 사용자·기기·워크스페이스별 프리셋을 서버 동기화 가능한 JSON으로 저장.
Bitget
Referenced
  • Long/Short 흐름 — 방향 명확한 주문 UX와 CTA 분리
  • Cross/Isolated — Margin Mode 즉시 전환
  • Progressive Disclosure — Advanced Order 점진 노출
  • Take Profit/Stop Loss — 주문 입력 단계 통합 TP/SL
  • Trigger 조건 — GTC · IOC · FOK 명시적 노출
Reframed → Beginner Mode에서 Limit/Market/Trigger 3개만 노출하고, Pro Mode에서 Advanced(OCO · Scaled · Iceberg · TWAP · Trailing) 접근. 색상 없이도 방향을 인지할 수 있도록 ▲▼ · LONG/SHORT · +/− 병기.
BitMart
Referenced
  • 맞춤형 레이아웃 — 사용자별 자유로운 모듈 배치
  • Mark Price 기준 — 미실현 손익 계산 기준 선택
  • 정보 압축 — 선물 화면에서 필요 정보의 밀도
  • Quick Symbol Switch — 심볼 즉시 전환 UX
Reframed → Density 3단계(Comfortable · Compact · Dense) 슬라이더로 밀도 자체를 사용자 선택으로. PnL Basis는 Mark/Last 세그먼트로 위젯 우측 하단에 상시 노출.
Non-goals
특정 거래소의 로고, 브랜드 컬러, 고유 아이콘 세트, 화면 배치의 픽셀 단위 복제, 트레이드 드레스는 사용하지 않습니다. 참고한 것은 기능적 UX 패턴뿐이며, 이를 Institutional Cool 디자인 언어로 완전히 재해석했습니다.
02 / INFORMATION ARCHITECTURE

앱 구조 · 위젯 관계

최상위 라우팅 · 트레이딩 화면의 위젯 관계 · 3개 주요 사용자 플로우.

Top-level routing
/ ├── /markets · /trade ← default · /trade?workspace=ai · /trade?mode=layout-edit · /portfolio · /analytics · /design-system
Flow 3 · AI 추세선 생성
User: "추세선 그려줘" → AI Thinking (3 steps) → Streaming Reply → Chart Overlay: AI Draft → User drags endpoint → AI 대화창에 반영 → Save as User Drawing
Flow 5 · AI Signal → Order
AI Analysis → Draft Signal → User Review → Approve Signal → Create Order Draft → Order Preview → Risk Check → Final Confirm → Simulated Submit
⚠ AI 대화 한마디만으로 실제 주문이 실행되는 UX는 존재하지 않습니다. 반드시 User Review → Approve → Preview → Risk Check → Final Confirm 5단계를 거칩니다.

10 / DEVELOPER HANDOFF

개발 이관 노트

Chart Domain Model · Overlay Adapter · Layout Engine · State Store 4개 축으로 분리. 어떤 실제 기술 스택에도 이식 가능.

Chart Adapter

프로토타입에서는 Canvas로 자체 구현했지만, 실제 개발 시 KLineChart 10.x로 교체 가능. Domain Model이 이미 KLineChart의 Overlay API와 호환됩니다.

  • Candle 데이터 형식 동일 (time · open · high · low · close · volume)
  • Overlay 타입: trend-line · horizontal · entry-zone · signal-marker · fib
  • KLineChart의 registerOverlay()에 커스텀 도형 등록 가능
Layout Engine

프로토타입에서는 자체 구현. 실제 개발 시 GridStack.js (MIT)로 교체 가능. Widget metadata 스키마가 이미 GridStack 호환.

  • x · y · w · h · minW · minH · maxW · maxH 필드명 동일
  • Undo/Redo · Save/Save As · Reset 히스토리 스택 30개
  • Breakpoint별 별도 레이아웃 저장 지원
State Management

위젯끼리는 Prop drilling 없이 하나의 Store에서 상태 공유. React Context + useReducer 또는 Zustand/Jotai 권장. Redux는 오버킬.

  • Slice: market · orderBook · trades · positions · orders · assets · overlays · signals · layout · tweaks
  • WebSocket 이벤트는 개별 slice로 dispatch
  • Optimistic UI: 주문 제출 즉시 상태 반영, 서버 응답 시 rollback 가능
Backend Contract

거래소 API를 UI 컴포넌트에 직접 의존시키지 않습니다. Exchange Adapter Interface를 두어 여러 거래소 병렬 연동.

  • Exchange Adapter: Binance · Bitget · BitMart · OKX · Bybit 각각 구현
  • Unified WebSocket schema로 UI는 하나의 스트림만 소비
  • 주문 전송은 별도 /orders/place · /orders/preview 엔드포인트
  • AI 서비스는 서버측 게이트웨이 경유 (LLM 프롬프트/도구 실행 격리)

Non-negotiables

Order Safety
  • AI 대화 한마디로 주문 실행 금지
  • Order Preview → Risk Check → Final Confirm 최소 3단계
  • 가격 이탈 · 잔고 부족 · 고레버리지 즉시 경고
Data Legibility
  • 모든 숫자에 tabular-nums 강제
  • 실시간 갱신 시 레이아웃 흔들림 금지
  • 과도한 애니메이션·flash 금지 · 짧고 절제된 피드백만
Accessibility
  • Long/Short은 색상 + 아이콘 + 텍스트 병기
  • 키보드로 주요 기능 접근 · Focus ring 명확
  • prefers-reduced-motion 완전 지원
