# e2e 상태 — 하네스는 살렸고, 스펙은 옛 앱을 대상으로 쓰여 있다

## 무엇이 고쳐졌나

`pnpm e2e` 는 **시작조차 못 하고 있었다.**

```
Error: Process from config.webServer exited early.
```

설정이 두 번째 웹 서버로 `pnpm --filter @quantumtrade/web dev` 를 띄우려 했는데 **그 패키지는 존재하지 않는다**. 프론트엔드는 이제 API 서버가 직접 서빙한다(`apps/api/src/static-web.ts` 가 `index.html`·`src`·`vendor`·`web-dist` 를 연다).

고친 것:

- 없는 웹 서버 항목 제거, `BASE_URL` 을 API 서버로
- `CORS_ALLOWED_ORIGINS` 를 API 오리진으로(브라우저가 그 오리진에서 요청한다)
- 포트 점검에서 5173(Vite) 제거 — 아무도 쓰지 않는 포트를 검사하면 무관한 프로세스 때문에 실패한다
- 스펙 134개 `goto('/x')` → `goto('/#/x')` (이 앱은 해시 라우터다)
- `getByLabel('email')` → `getByLabel('Email', { exact: true })` — 부분 일치가 체크박스 라벨 문구까지 잡아 strict 위반이 되고, 그것이 타임아웃으로 보였다

이제 하네스가 실제로 돌고 **테스트가 진짜 이유로 실패한다.** 그 차이가 이 작업의 목적이다.

## 부수 효과: 접근성 결함이 드러났다

인증 화면 입력칸에 `aria-label` 도 `htmlFor` 도 **하나도 없었다**. 라벨이 `<span>` 으로만 있어 input 과 연결되지 않았다.

- 스크린리더 사용자는 어느 칸이 이메일인지 알 수 없다
- `getByLabel` 이 칸을 찾지 못해 인증 흐름 테스트가 전부 실패한다

`src/pages-auth.jsx` 의 16곳에 `aria-label={t('키')}` 를 붙였다. 사전 키를 그대로 쓰므로 번역이 함께 따라온다.

**아직 남은 곳**: `pages-user.jsx` 15개, `pages-more.jsx` 16개, `widgets.jsx` 15개 입력칸에 접근성 라벨이 없다.

## 남은 격차 — 스펙이 존재하지 않는 UI 를 기대한다

| 기대 | 실제 |
|---|---|
| `getByTestId(...)` 11곳 | 앱에 `data-testid` **0개** |
| `.card button.btn--primary` 3곳 | 현재 마크업과 다름 |
| `/trade/ai` `/trade/order` `/trade/layout` `/status` | 존재하지 않는 라우트 |

즉 스펙 24개는 **구조가 다른 예전 앱**을 대상으로 쓰였다. 선택자를 하나씩 맞추는 것은 스펙을 새로 쓰는 일에 가깝고, 그 전에 결정이 필요하다.

## 진행 상황

역할·라벨 기반으로 다시 쓰는 방향으로 결정했다. `flow-k-auth.spec.ts` 를 먼저 옮겼고 **통과한다**(가입 → 로그인 상태 → 로그아웃 → 재로그인, 그리고 짧은 비밀번호 거부).

옮기면서 접근성 결함 두 가지가 더 드러났다 — 이 방향을 택한 근거다:

- 아이콘 버튼 **87개**가 `title` 만 갖고 `aria-label` 이 없었다. `title` 은 접근성 이름으로 쓰이지 않는다. 계정 버튼은 안에 이니셜 한 글자가 있어 접근성 이름이 `"A"` 였다 — 스크린리더 사용자에게 "A 버튼" 이다.
- 계정 버튼의 `aria-label` 에 이메일 인자가 빠져 있었다(`t('profile_signed_in_as')` 만 호출).

두 번째 테스트에서 배운 것: 짧은 비밀번호로 제출 버튼을 누르려 했는데 클릭이 타임아웃됐다. 버그가 아니라 **버튼이 비활성화**되는 더 나은 동작이었다. 눌러서 오류를 보여주는 것보다 낫다. 스펙을 "비활성 상태" 검증으로 바꿨다.

### 전환 완료 — 4개 스펙 12개 검사 통과 (30초)

값이 높은 것부터 골라 옮겼다. 주문과 차트가 고객이 실제로 쓰는 핵심이다.

| 스펙 | 검사 | 무엇을 지키는가 |
|---|---|---|
| `flow-k-auth` | 2 | 가입 → 로그인 상태 → 로그아웃 → 재로그인, 짧은 비밀번호 거부 |
| `flow-m-chart-render` | 4 | 봉이 실제로 들어오고 **픽셀이 그려지는가**, 심볼·주기 변경 시 재적재 |
| `flow-c-order` | 3 | 키 없는 계정이 주문을 낼 수 없고 이유를 듣는가, **주문 요청이 실제로 안 나가는가** |
| `flow-h-order-full` | 3 | 리스크 게이트 전체 목록과 **판단 근거**가 응답에 있는가, 측정 불가를 숨기지 않는가 |

전환하며 알게 된 사실들(다음 사람이 다시 조사하지 않도록):

- **차트는 로그인 상태에서만 마운트된다.** 로그아웃 상태로 `/#/trade` 를 열면 `ChartKlineUtil.debug()` 가 빈 배열이다. 원본 스펙이 로그인 없이 차트를 검사해 "봉 0개" 로 실패했다 — 차트가 깨진 게 아니라 애초에 없었다.
- **키가 없으면 주문 흐름이 시작조차 되지 않는다.** 화면이 "Connect your exchange account first" 라고 말한다. 결함이 아니라 비수탁 구조다. 그래서 스펙은 **주문 POST 가 한 건도 나가지 않는지**까지 확인한다 — 문구만 보면 "안내는 뜨는데 주문은 나가는" 상태를 놓친다.
- **기본 배치에 종목 목록 위젯이 없다.** 화면에서 심볼을 바꿀 컨트롤을 찾을 수 없다(실측 0개). 그래서 심볼 변경은 어댑터에 직접 지시하고 재적재를 확인한다. 없는 UI 를 있는 것처럼 테스트하지 않는다.
- 체결까지의 경로는 e2e 로 덮지 않는다. 실 거래소 자격증명이 필요하고 AI 응답은 비결정적이다. 서버 테스트가 덮는다(`trading-routes`·`policy-unlimited`·`oauth-scope`·`mode-neutral`). 스펙 주석에 어느 테스트가 그 역할인지 적어 두었다.

### 주문 경로 전환 완료 — 31개 검사 통과 (1.1분)

이번 세션에 주문 경로를 여러 군데 고쳤는데(심볼 카탈로그·최소수량·잔고 확인·다중 패널 규격) 그 수정을 지켜줄 e2e 가 없었다. 그래서 주문 관련 스펙 두 개를 옮겼다.

| 스펙 | 검사 | 비고 |
|---|---|---|
| `flow-t-order-validation` | 10 | 검증 계약(멱등키·미지 필드 거부·제출 엔드포인트 부재) |
| `flow-o-order-portfolio` | 9 | 주문 입력·목록·자산의 정직성 |

`flow-t` 는 `getByTestId('signup-ok')` 한 곳만 막고 있었다 — 앱에 `data-testid` 가 0개라 늘 실패했다. 가입 성공을 **결과**(로그인 상태로 거래 화면 도달)로 판정하게 바꿨다. 나머지 세 검사(B4-7·8·9)는 존재하지 않는 화면(`oe-qty`·`oe-preview`·`server-validation` 패널)을 대상으로 해서, **의도만 남기고** 라우트를 직접 부르는 방식으로 옮겼다. 실행 시간도 1.7분 → 16초로 줄었다(타임아웃이 사라졌으므로).

`flow-o` 는 441줄·32개 검사였고 `data-testid` 를 144번 썼다. 전부 실패 상태였다. 실제 화면에 있는 것만 남겨 9개로 줄였다:

- 최소수량 경고가 **숫자를 말하는지**, 그리고 유효한 값에서 **사라지는지**(켜지는 것만 보면 "항상 켜진" 경고를 놓친다)
- 키가 없을 때 잔고를 0 으로 꾸미지 않는지
- 주문 화면을 열고 값을 넣는 것만으로 실거래 경로가 호출되지 않는지
- 킬스위치 상태와 근거가 응답에 있는지
- 목록이 비었을 때 이유를 말하는지
- 비활성 버튼에 이유가 붙어 있는지

**뺀 것과 이유**: AI 6개(응답이 유료·비결정적 — 서버 테스트가 덮는다), '최종 확인 → 모의 체결' 계열(그 UI 가 없고 실주문은 거래소 키가 필요하다), '모의 주문이 포지션에 나타난다'(모의 체결 경로가 없다). 없는 UI 를 있는 것처럼 테스트하지 않는다 — 그게 이 파일이 오래 아무것도 지키지 못한 이유였다.

### 남은 스펙 12개

레이아웃 기하·테마·언어·AI 오버레이·재접속 등이다. 깨져도 고객 돈에 영향이 없어 우선순위가 낮다. 같은 방식으로 옮긴다. 규칙:

- `getByRole` / `getByLabel` 로 찾고, 클래스·`data-testid` 로 찾지 않는다
- 화면이 선언한 **실제 역할**을 쓴다(로그아웃은 `button` 이 아니라 `menuitem` 이다)
- 로그인·가입 직후 면책 대화상자가 클릭을 가로챈다 — 먼저 닫는다
- 커스텀 체크박스는 `.check()` 가 아니라 감싸는 `label.chk` 를 클릭한다

## 결정이 필요한 것

`data-testid` 를 앱에 넣을지가 갈림길이다.

- **넣는다**: 스펙이 안정된 선택자를 갖는다. 대신 마크업에 테스트 전용 속성이 늘고, 어떤 요소에 붙일지 기준이 필요하다.
- **넣지 않는다**: 스펙을 역할·라벨 기반(`getByRole`, `getByLabel`)으로 다시 쓴다. 접근성이 함께 개선되지만(위에서 본 것처럼) 작업량이 크다.

두 번째가 더 낫다고 보는 이유: `getByLabel` 을 고치는 과정에서 실제 접근성 결함이 드러났다. 역할·라벨로 테스트를 쓰면 **테스트가 접근성을 강제한다.** 다만 24개 스펙을 다시 쓰는 일이므로 별도 작업으로 잡아야 한다.

## 다른 두 스위트

`tests/e2e-admin` 은 `@quantumtrade/admin` 패키지를 빌드·프리뷰하려 하는데 그 패키지도 없다. `tests/e2e-mfa` 는 `@quantumtrade/web` 을 쓴다. 둘 다 같은 이유로 돌지 않는다. 이 문서의 첫 수정과 같은 방식으로 고칠 수 있지만, 스펙 격차는 위와 동일하게 남는다.
