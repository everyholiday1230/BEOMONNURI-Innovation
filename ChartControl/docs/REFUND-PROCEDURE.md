# 환불 처리 절차 (수동)

**상태: 코드 없음. 사람이 처리한다.** 감사에서 "지킬 수 없는 약속" 으로 지적됐고,
확인한 결과 **약속 자체는 지킬 수 있다** — 문구가 이메일 문의를 통한 수동 처리를
명시하고 있고, 아직 환불 대상 결제가 **0건**이다(`point_orders` 22건 중 `paid` 0건).

그래서 코드를 지금 만들지 않는다. 대신 **어떻게 판정하고 실행하는지**를 여기에 적는다.
첫 실제 결제가 생기기 전에 이 문서를 읽고 자동화 여부를 결정한다.

## 우리가 한 약속 (locales `pt_withdraw_right_body`)

> 구매한 포인트를 **쓰지 않았다면** 결제일로부터 **7일 안에** 전액 환불을 요청할 수
> 있다. 쓴 뒤에는 그 구매분은 환불되지 않는다. 이메일로 알려주면 **원래 결제수단으로**
> 돌려준다.

## ★★ 판정이 어려운 지점 — "썼는지" 를 어떻게 아는가

잔액은 `point_ledger` 의 `SUM(delta)` 다. **어느 구매분의 포인트를 썼는지 추적하지
않는다.** 그래서 "이 구매는 미사용" 을 엄밀히 증명할 수 없다.

실무 판정 규칙(보수적으로, 고객에게 유리하게):

1. 해당 구매 이후의 **차감 합계**를 구한다
   ```sql
   SELECT COALESCE(SUM(-delta), 0) AS spent_after
     FROM point_ledger
    WHERE user_id = $1 AND delta < 0 AND created_at > $구매시각;
   ```
2. `spent_after = 0` → **미사용 확정.** 전액 환불한다.
3. `spent_after > 0` → 구매분을 썼을 수 있다. 그때는 **현재 잔액**을 본다.
   현재 잔액이 구매 수량 이상이면 그 구매분은 남아 있다고 보고 환불한다
   (선입선출로 보면 이전 잔액이 먼저 소진되므로 고객에게 유리한 해석이다).
4. 그래도 애매하면 **환불하는 쪽**을 택한다. 소액이고, 분쟁·차지백 비용이 더 크다.

## 실행 절차

1. **결제 확인** — `point_orders` 에서 해당 주문의 `status='paid'` 와 결제일 확인.
   7일 경과 여부를 결제일 기준으로 판정한다(요청일이 아니다).
2. **미사용 판정** — 위 규칙.
3. **PayPal 환불** — 대시보드에서 해당 거래를 찾아 환불한다.
   ★ 코드에는 환불 API 호출이 **없다**(`providers.ts` 에 refund 0건). 자동화하려면
   `POST /v2/payments/captures/{id}/refund` 를 붙여야 한다.
4. **포인트 회수** — 환불한 만큼 차감 원장을 남긴다. **잔액이 음수가 되지 않게** 한다:
   ```sql
   -- points-repo 의 spendMetered 와 같은 방식(잔액까지만 차감)을 쓸 것.
   -- ref_type='refund' 로 남겨 나중에 집계할 수 있게 한다.
   ```
   ★ 지금 `ref_type='refund'` 를 쓰는 코드가 0건이다. 수동으로 넣을 때도 이 값을 쓴다.
5. **고객 통지** — 처리 결과와 환불 금액·수단을 회신한다.
6. **기록** — 환불 근거(미사용 판정 값, PayPal 거래 id)를 남긴다.
   `audit_logs` 에 남기는 것이 맞고, 지금은 수동이므로 이메일 스레드를 증거로 보관한다.

## 자동화 판단 기준

지금 만들지 않는 이유: 대상이 0건이고, 판정 규칙이 위처럼 **해석을 포함**한다. 코드로
굳히면 애매한 사례를 기계가 잘못 자르는데, 그 손해가 수동 처리 비용보다 크다.

**만들어야 할 시점**: 월 환불 요청이 5건을 넘거나, 구독 환불(포인트가 아닌 구독료)
요청이 들어올 때. 그때는
- `providers.ts` 에 PayPal refund 호출 추가
- 구매 단위 추적(`point_ledger` 에 구매 참조를 남기거나 lot 단위 테이블)
- 관리자 화면에 환불 버튼 + 감사기록

## 구독료 환불은 이 문서 범위가 아니다

구독은 해지 시 **남은 기간을 그대로 쓰는** 방식이다(`canceled` + 기간 유지). 일할
환불을 약속한 문구는 없다. 약속을 추가하려면 문구를 먼저 고치고 그 다음 코드다 —
순서를 바꾸면 지킬 수 없는 약속이 된다.
