# 보안 안내

이 문서는 서비스가 **실제로 구현해 둔** 보안 조치를 설명합니다. 계획이나 목표가 아니라 지금 동작하는 것만 적었습니다.

## 1. 회사는 이용자의 자금을 보관하지 않습니다

- 이용자의 자금은 **이용자 본인의 거래소 계정**에 있습니다. 회사에는 입금 주소가 없고, 지갑도 없으며, 어떤 지갑의 키도 보유하지 않습니다.
- 그래서 회사가 해킹당해도 이용자의 자금을 회사가 옮길 수 없습니다. 옮길 수단 자체가 없습니다.

## 2. API 키는 출금 권한을 요구하지 않습니다

- 서비스가 요구하는 권한은 **조회와 거래**입니다. **출금 권한은 의도적으로 요구하지 않습니다.**
- 따라서 키가 유출되더라도 그 키로 자금을 인출할 수 없습니다. 이용자는 거래소에서 키를 발급할 때 출금 권한을 주지 마십시오.
- 회사의 어떤 직원도, 어떤 권한 등급에서도 이용자의 자금을 출금할 수 없습니다.

## 3. API 키는 암호화해 저장합니다

- 이용자가 연결한 키는 봉투 암호화(envelope encryption)로 저장됩니다. 평문으로 기록하지 않습니다.
- 관리자 화면에서도 키의 원문은 표시되지 않습니다.
- 키를 저장한 뒤 거래소에 실제로 조회를 한 번 보내 사용 가능한지 확인합니다. 저장만 하고 "연결됨"으로 표시하지 않습니다.

## 4. 계정 보안

- 비밀번호는 해시로 저장합니다. 평문 비밀번호는 저장하지 않습니다.
- 2단계 인증(TOTP)을 지원합니다. 인증 앱의 6자리 코드를 사용합니다.
- 로그인 시도에는 횟수 제한이 있습니다. 반복 실패 시 일정 시간 잠깁니다.
- 세션 쿠키에는 Secure·HttpOnly 속성이 적용되며, 상태를 바꾸는 요청에는 CSRF 토큰 검증이 적용됩니다.
- 계정을 정지하면 그 계정의 세션이 즉시 무효화됩니다.

## 5. 주문 경로의 안전장치

- 주문은 화면 계산을 신뢰하지 않고 **서버가 다시 검증**합니다. 최소 수량·호가 단위·가격 이탈·레버리지 상한·일일 한도·미결제 포지션 수를 서버에서 확인합니다.
- 실주문은 여러 조건을 모두 만족해야 전송됩니다. 하나라도 어긋나면 전송하지 않고 이유를 화면에 표시합니다.
- 비상 정지 장치(kill switch)가 있습니다. 작동시키면 모든 실주문 전송이 즉시 중단됩니다.
- 관리자는 이용자의 주문을 대신 넣거나, 고치거나, 취소할 수 없습니다. 이것은 제한이 아니라 설계입니다.

## 6. 기록과 감사

- 관리자의 조작은 감사 로그에 남습니다. 로그는 추가만 가능하며 수정·삭제하지 않습니다.
- 계정 정지·재개, 권한 변경, 자격증명 삭제 같은 되돌리기 어려운 조작은 이유를 함께 기록합니다.
- AI 분석의 사용량은 기록하지만, **프롬프트와 응답 본문은 저장하지 않습니다.**

## 7. 전송 구간 보호

- 서비스는 HTTPS로만 제공됩니다. HSTS 헤더로 브라우저가 평문 접속을 시도하지 않게 합니다.
- 콘텐츠 보안 정책(CSP), 클릭재킹 차단(X-Frame-Options: DENY), MIME 스니핑 차단(X-Content-Type-Options)을 적용합니다.

## 8. 회사가 하지 않는 것

- 신분증·셀카·주소 증명을 받지 않습니다. 본인 확인은 거래소가 수행합니다. 그래서 회사에는 유출될 신분 서류가 없습니다.
- 이용자의 자금을 대신 운용하지 않습니다. 자동 매매를 대신 실행하지 않습니다.
- 이용자에게 투자 자문을 제공하지 않습니다.

## 10. 이 문서의 한계

이 문서는 구현된 조치를 설명한 것이며, 어떤 공격도 성공하지 못한다는 보장이 아닙니다. 완전한 보안은 존재하지 않습니다. 이용자께서도 거래소 계정의 2단계 인증을 켜고, API 키에 출금 권한을 주지 않으시기를 권합니다.
