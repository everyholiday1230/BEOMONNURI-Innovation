```sql

FROM point_ledger WHERE memo LIKE 'signup grant%' ORDER BY created_at DESC;

-- 가입자 수와 가입 지급 건수가 맞나 (어긋나면 누락이다)

       (SELECT count(*) FROM point_ledger WHERE memo LIKE 'signup grant%') AS signup_grants;
```

의도한 것이면 그대로 두고, 아니면 값을 넣는다.

매 렌더마다 새 함수가 되어 effect 의존성이 바뀌고, effect 가 다시 붙는다.
유휴 상태에서도 `overrideOverlay` 가 초당 약 2회 돈다.

해결법은 이미 같은 파일에 있다 — **선 몸통 드래그에 쓴 ref 패턴**을 그대로 쓰면 된다
(`lineDragRef`, `overlaysRef`, `onOverlayChangeRef`, `activeToolRef`).

★ **주의: 이 effect 의 의존성 배열은 `[]` 로 유지해야 한다.** 인라인 콜백을
의존성에 넣으면 매 렌더 재부착되어 진행 중인 드래그가 사라진다. 실제로 겪었다.

### 4-2. 라이브러리 기본값이 새는지 전수 점검

klinecharts 도형에 스타일을 일부만 주면 나머지가 **라이브러리 기본값**으로 채워진다.
이번에 `text.backgroundColor` 가 그랬다 — 지정하지 않으면 `#1677ff` 파란 배경이
글자 뒤에 깔린다. 운영자가 "라벨 뒤에 파란 게 있다" 고 보고한 것이 이것이다.

**`rect`·`line`·`polygon` 에도 같은 일이 있는지 아직 안 봤다.**

★ 규칙: `type: 'text'` 도형에는 `backgroundColor: 'transparent'` 를 **반드시** 준다.

### 4-3. 웹훅 메일 알림 배선

분쟁이 감지되면 `payment_webhook_events` 에 적힌다. **그것만으로는 아무도 보지
않는다.** 메일 알림을 붙여야 한다. `ErrorAlerterDeps` 의 스코프 정리가 먼저 필요하다.

## 6. 이 코드베이스의 함정 — 모르면 반드시 밟는다

### 6-1. JSX 주석은 중괄호로 감싸야 한다 ★★★

중괄호 없이 블록 주석만 적으면 **주석이 아니라 화면에 나오는 글자**다.
문법 오류가 아니므로 **컴파일도 eslint 도 통과한다.**

실제 사고: 접힌 사이드바에 설명 문단이 그대로 노출됐다.

**주석 본문에 블록 주석 닫는 기호를 적지 말 것.** 주석이 그 자리에서 끝나고 나머지가
JSX 식으로 파싱돼 파일 전체가 깨진다. 이 저장소는 "예전에 이렇게 적어서 깨졌다" 를
주석에 남기는 규약이라 특히 밟기 쉽다.

지금은 빌드(`scripts/build-web.mjs`)와 시험(`jsx-comment-leak.test.ts`)이 둘 다 막는다.

### 6-2. 소스 검사 시험을 쓸 때

이 저장소는 주석에 실패 사례를 그대로 남긴다. 그래서 정규식으로 소스를 훑으면
**자기 설명 주석이 잡힌다.** 실제로 여러 번 겪었다.

- **주석을 먼저 제거**하고 검사한다
- 검사 코드 안에서는 기호를 `'/' + '*'` 처럼 **조립**한다
- 원본보다 **컴파일 결과**를 보는 편이 판정이 흐릿하지 않다
- `({...}) => {` 의 구조분해 브레이스에 주의
- 축약 속성은 콜론이 없다 (`{ colors }` vs `{ colors: colors }`)
- 같은 문자열이 두 목적으로 쓰이면 검사가 헛돈다
- **"아무것도 없음" 을 확인하는 시험은 검사가 고장나도 통과한다** — 일부러 깨진
  입력을 만들어 잡히는지 시험 안에서 함께 확인할 것

### 6-3. 새 시험을 넣으면 반드시 역검증

고친 것을 되돌려 **시험이 실제로 실패하는지** 확인한다. 이 저장소에서 통과하지만
아무것도 검사하지 않는 시험을 여러 번 만들었다.

### 6-4. 차트(`src/chart-kline.jsx`) 불변식

- **`createPointFigures` 의 bounding 은 캔들 패널(폭 330), `createYAxisFigures` 의
  bounding 은 Y축(폭 64)이다.** 좌표계가 다르다. 패널 콜백에서 축에 그릴 수 없다.
- `type: 'text'` 도형에 `backgroundColor: 'transparent'` 필수 (§4-2)
- **인라인 콜백을 effect 의존성에 넣지 말 것** (§4-1)
- **`useEffect` 의존성 배열은 렌더 중 평가된다.** `const` 선언이 그 아래에 있으면
  TDZ 로 화면 전체가 죽는다.
- 라벨 겹침 회피: 예약 영역을 **하나의 상자로 합치지 말 것.** 레전드는 오른쪽 위에
  좁게, HUD 는 위쪽에 넓게 있어 실제 모양이 ㄱ자다. 합치면 빈 공간까지 예약되고
  피하려던 것 대신 엉뚱한 것과 부딪힌다(실제로 그렇게 다른 라벨과 겹쳤다).
- 라벨은 **세로보다 가로로 비킨다.** 라벨이 자기 선에서 멀어지면 어느 선의 값인지
  알 수 없다 — 세로 거리가 곧 정확도다.
- **색 토큰 이름이 다르다고 값이 다른 것은 아니다.** `--color-trade-long` 과
  `--chart-candle-up` 은 값이 완전히 같다(`oklch(72% 0.14 175)`). 구분이 필요한
  두 요소에 이 둘을 쓰면 구분되지 않는다.
- 글자 폭은 **추정하지 말고 캔버스 `measureText` 로 실측**한다. 추정은 약 7% 좁게
  나와 글자가 상자 밖으로 나갔다. 실측할 때 **그리는 글꼴(family·weight)을 그대로
  넘겨야** 맞는 값이 나온다.

### 6-5. 로컬 검증 패턴

