## 1. 좌표계 — 가장 많이 틀린 곳

### 1-1. ★★★ 두 콜백의 좌표계가 다르다 (`chart-kline.jsx:560`)

실측(2026-09-15):
```
createPointFigures   bounding = { width: 330, left:   0, right: 64 }   ← 캔들 패널
createYAxisFigures   bounding = { width:  64, left: 330, right:  0 }   ← Y축 캔버스
```
**패널 콜백에서 축에 그릴 수 없다.** 예전 구현이 정확히 이 실수를 했고, 주석에는
"가격 라벨 (오른쪽 축 위 알약)" 이라고 적혀 있었지만 실제로는 캔들 위에 그려졌다.

### 1-2. ★★★ 가격은 오른쪽 축에 그린다 (`:788`)
운영자가 다섯 번 넘게 요청한 항목. 실시간 가격 배지와 같은 자리여야 한다.

### 1-3. ★★★ 진입·TP·SL 세 가격을 모두 축에 그린다 (`:1014`)
패널 콜백에서는 축에 닿을 수 없으므로 **같은 계산을 축 콜백에서 한 번 더** 한다.
색은 패널과 동일해야 한다 — 축 배지 색과 선 색이 다르면 어느 선의 값인지 모른다.

### 1-4. ★★★ `bounding` 을 반드시 넘긴다 (`:355`)
`ext.paneWidth` 같은 값은 오버레이 데이터에 **없다.** 처음에 그렇게 썼더니 항상 0 이
되어 **축약이 한 번도 동작하지 않았다.** 조용히 아무 일도 안 하는 코드였다.

### 1-5. ★★ 실패하면 0 을 돌려준다 (`:332`)
0 은 "모른다" 이고, 호출부는 그때 축약하지 않는다.

### 1-6. ★★ 라벨 폭 = 마지막 봉 오른쪽의 빈 공간 (`:382`, `:324`)
"캔들보다 더 오른쪽" 요청을 지키려면 그 여백을 실측해야 한다.

### 1-7. ★★ 기본 Y축 도형을 쓰지 않고 직접 그린다 (`:762`)
우리가 축에 그리면 라이브러리 기본 축 도형을 끈다 — 안 끄면 배지가 두 개 겹친다.

운영자 보고 "라벨 뒤에 파란 게 있다" 가 이것이다. → `'transparent'` 를 명시한다.

- 결과: 글자가 상자를 넘쳤다 (운영자 보고: "네모칸 밖으로 조금 넘어간다")
- ★★ 실측할 때 **그리는 글꼴(family·weight)을 그대로 넘겨야** 맞다
- ★★ 캔버스를 못 만드는 환경(시험 등)에서는 추정으로 떨어진다 (`:455`) — 폭을 모른다고 그리지 않는 것보다 낫다

## 8. 상태 동기화 — 진행 중 조작을 잃지 않는다

### 8-1. ★★★ 최신 값을 ref 로 읽는다 (`:2245`)
의존성을 `[overlays, onOverlayChange, activeTool]` 로 두었더니, 상위가
`onOverlayChange={(id, ov) => updateOverlay(id, ov)}` 처럼 **인라인 화살표**를 넘기므로
매 렌더 새 함수가 되고 효과가 **매 렌더 재부착**됐다. 진행 중 드래그가 사라진다.
→ `lineDragRef` · `overlaysRef` · `onOverlayChangeRef` · `activeToolRef`, 의존성 `[]` 유지.

### 8-2. ★★★ 끌고 있는 선은 건드리지 않는다 (`:2284`)
동기화 효과가 상태를 차트에 되쓰는데, 드래그 중에는 상태가 아직 옛 가격이다.
그 사이 렌더가 한 번 일어나면(**시세 틱 하나면 충분**) 선이 손가락 아래에서 원래
자리로 튕긴다.

## 11. AI 수식 DSL (`src/formula-dsl.js`)

### 허용 함수 (10개, 이것 외 전부 거부)
```
SMA  EMA  STDDEV  REF  DELTA  ABS  MIN  MAX  POW  SQRT
```

### 인자 개수 (ARITY)
```
SMA:2  EMA:2  STDDEV:2  REF:2  DELTA:2
MIN:2  MAX:2
ABS:1  SQRT:1
POW:1 또는 2   ← 지수 생략 시 평가기가 2 로 본다
```

### 연산자
```
+  -  *  /  (  )  ,
```
★ **비교 연산자(`>`, `<`)와 논리 연산자가 없다.** 조건을 표현할 수 없다.
즉 "MACD 골든크로스면 매수" 같은 규칙은 **DSL 로 쓸 수 없다.**
★ MACD 내장 함수도 없다 (`EMA(close,12) - EMA(close,26)` 로 우회는 가능).

### 수치 한도
| 항목 | 값 | 상수 |
|---|---|---|
| 수식 길이 | 400자 | `MAX_LEN` |
| AST 노드 수 | 80개 | `MAX_NODES` |
| 함수 중첩 | 3단계 | `MAX_CALL_DEPTH` |

### ★★ 중첩 단계를 실제로 센다 (`:111`)
이 자리에 있던 `let depth = 1;` 은 **읽는 곳이 없어 아무것도 막지 않았다.**

### 서버가 직접 파싱한다 (`indicator-formula` 시험)
화이트리스트 밖 이름 거부(코드 주입 차단) · 괄호 균형 · 길이 · 노드 수 · 인자 수 ·
중첩. 통과한 식은 **AST 를 함께 돌려준다** — 통과 사실이 파싱 성공을 뜻하게 한다.
3단계 중첩은 통과해야 한다(상한이 정상 사용을 막지 않는다).

## 12. AI 차트 명령 규칙 (`packages/ai/src/`)

### 허용 명령 (14개)
```
createTrendLine  createHorizontalLevel  createSupportResistance
createEntryZone  createStopLoss  createTakeProfit
createLongMarker  createShortMarker  createInvalidationLevel
addIndicator  removeIndicator
updateOverlay  hideOverlay  deleteOverlay
```

### 허용 지표 (27종)
```
가격창 겹침 : MA EMA SMA BOLL BBI SAR AVP
거래량      : VOL OBV VR EMV PVT
모멘텀      : MACD RSI KDJ CCI WR BIAS BRAR CR
그 밖       : ROC MTM AO PSY DMI DMA TRIX
```

### 행동 규칙
- **한 번에 한 동작.** `propose_chart_command` 는 명령 하나만.
- **추세선은 실제 캔들 timestamp 두 점**으로 그린다.
- **지표가 화면에 없으면 AI 가 스스로 켠다.** 이용자에게 "켜세요" 라고 하지 않는다.
- **피보나치는 그릴 수 없다.** 명령이 없으므로 그렇게 말하고 수동 도구를 안내한다.
- **매수/매도 신호를 만들 수 없고, 패턴(골든크로스·RSI 다이버전스·돌파)을
  감지할 수 없다.** 4단계 절차:
  1. 못 한다고 한 문장으로 먼저 말한다
  2. 같은 답변에서 양방향/한방향을 묻고 **양쪽 근거를 동일 분량으로** 제시한 뒤 멈춘다
  3. 방향을 받으면 진입·손절·목표를 숫자로 내놓되 **각 숫자의 기계적 규칙과 근거 봉**을
     밝히고, 예측이 아니라고 말하고 확인을 구한다. **이 단계는 텍스트만** — 도구 호출 금지
  4. 확인 후에만 그린다
- **방향을 먼저 말하지 않는다.** 어느 쪽이 유력하냐고 물어도 예측하지 않는다.
  단서를 붙여도 중립이 되지 않는다.
- **내 숫자를 이용자의 것으로 말하지 않는다.** `review_setup` 은 이용자가 방향과
  값을 **둘 다** 준 경우에만.
- **감지하지 않은 것을 감지한 것처럼 이름 붙이지 않는다.** 그냥 RSI 를
  "RSI 다이버전스" 라고 부르지 않는다.
- **그리지 않은 것을 그렸다고 하지 않는다.**
- 숫자를 지어내지 않는다 — 도구 결과나 `MARKET_DATA` 에 있는 값만 말한다.
- 지표 이름은 번역하지 않는다 ("RSI" → "상대강도지수" 로 바꾸면 범례와 어긋난다).

### 화면 지표 값의 출처를 밝힌다 (`apps/api/src/index.ts:4474`)
`screen.indicatorValues` 는 **고객 브라우저가 계산한 값**이다. 서버 검증값(봉·가격)과
같은 곳에 섞지 않고 `screen` 안에 두고, 프롬프트에 그 사실을 적는다.
개수 상한: 지표 12개 · 그림 20개.

## 16. 소스 검사 시험을 쓸 때의 함정

이 저장소는 주석에 실패 사례를 그대로 남긴다. 그래서 정규식으로 소스를 훑으면
**자기 설명 주석이 잡힌다.** 여러 번 겪었다.

- **주석을 먼저 제거**하고 검사한다
- 검사 코드 안에서는 기호를 `'/' + '*'` 처럼 **조립**한다
- 원본보다 **컴파일 결과**를 보는 편이 판정이 흐릿하지 않다
- `({...}) => {` 의 구조분해 브레이스 주의
- 축약 속성은 콜론이 없다 (`{ colors }` vs `{ colors: colors }`)
- 같은 문자열이 두 목적으로 쓰이면 검사가 헛돈다
- **"아무것도 없음" 을 확인하는 시험은 검사가 고장나도 통과한다**
- JSX 주석은 `{ }` 로 감싼다. 안 감싸면 **화면에 글자로 나온다**(실제 사고).
  주석 본문에 블록 주석 닫는 기호를 적지 말 것 — 파일이 깨진다.
